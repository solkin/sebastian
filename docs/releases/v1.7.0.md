# Sebastian v1.7.0

This release brings the gateway fixes of Birak v2.1 to Sebastian: an S3 copy
that emptied objects, gateways that opened on missing credentials, a web UI
request that could delete the whole root directory, and the robustness gaps
around them. Startup now refuses configurations that earlier releases accepted
with a warning; read **Upgrade from v1.6.1** before rolling out.

## Changes

### Data safety

- **S3 CopyObject copies.** It used to be handled as an empty PutObject, so
  `aws s3 cp`/`mv` between keys, or a copy onto itself to change metadata,
  replaced the object with zero bytes. CopyObject and UploadPartCopy are now
  implemented: the source is staged next to the destination and published
  atomically; a source replaced during the copy answers `503 SlowDown`. A
  self-copy changes nothing.
- **The web UI can no longer delete or rename the root.** `POST /_api/delete`
  with a path such as `apps/..` resolved to the root directory and removed
  everything below it. Such paths now answer `400`.

### Security and configuration

- **Gateways fail closed.** An enabled gateway needs both credentials; with
  neither it starts only with the new `allow_anonymous: true`
  (`SEBASTIAN_*_ALLOW_ANONYMOUS`). One credential alone is always refused — an
  empty S3 secret or password used to be a value anyone could sign or log in
  with, in S3, WebDAV, the web UI and SFTP alike. Values starting with
  `changeme` are refused.
- A nonempty environment value that does not parse stops startup instead of
  silently keeping the default. A gateway that fails, such as one whose port is
  taken, now stops the server with exit status 1.
- The access log no longer records presigned URL signatures or credentials.
- Presigned URLs are limited to 7 days and their credential date must match
  `X-Amz-Date`. Every spelling of `.sebastian` and of scratch prefixes is
  reserved on case-insensitive filesystems; NUL bytes are refused by every
  gateway. Web UI and SFTP errors no longer reveal filesystem paths.

### S3 behaviour

- Folder markers (`PUT prefix/` with an empty body) create the directory instead
  of a zero-byte file that broke later uploads below it.
- GET and HEAD evaluate `If-Match`, `If-None-Match`, `If-Modified-Since` and
  `If-Unmodified-Since` and answer `412` as XML without a misleading
  `Content-Length`; an unsatisfiable range answers `416 InvalidRange`. PUT and
  CompleteMultipartUpload honour `If-None-Match: *` and `If-Match` atomically.
- Errors that used to be `500` or `NoSuchKey` have S3 codes: `NoSuchBucket`,
  `KeyTooLongError`, `ParentIsObject`, `ObjectExistsAsDirectory`,
  `InvalidArgument`.
- A repeated CompleteMultipartUpload returns the original result; its body is
  checked against `Content-MD5`/`x-amz-content-sha256`. PUT, Complete and Copy
  return the same ETag as a later HEAD.
- Uploads whose declared length exceeds `max_upload_bytes` are refused with
  `413` before the body is read. Content-Type is derived from a safe set of
  extensions (`.apk`, images, `.json`, `.txt`, `.pdf`, `.zip`);
  `X-Content-Type-Options: nosniff` is always sent.

### Web UI, WebDAV and SFTP

- Web UI uploads stream into the served directory instead of `os.TempDir()`,
  publish nothing from a form that fails, and answer `413` over
  `max_upload_bytes`. A file uploaded into a bucket on another mount is copied
  there.
- Large directories list about five times faster with a fraction of the memory;
  at most four listings run at once.
- Invalid names answer `400` and conflicts `409` in the web UI instead of `500`.
- Client aborts in the web UI, WebDAV and S3 are no longer logged as errors.
- SFTP: a half-configured username/password pair admits nobody.

### Operations

- Every gateway abandons transfers that make no progress for five minutes;
  slow transfers that keep moving are unaffected.
- Stopping drains open transfers for at most 8 seconds, in parallel, below
  Docker's default grace period.
- The access log adds duration, client address and `X-Forwarded-For`, and can be
  turned off with `access_log: false` (`SEBASTIAN_ACCESS_LOG=false`).
- `sebastiand -version`. The image includes `find-aws-chunked`, which lists
  objects that may still hold aws-chunked framing stored by v1.6.0 or earlier.
- `docker-compose.yml` pins the release, requires every credential, waits 30 s
  on stop and rotates logs. The nginx example streams downloads, keeps upstream
  connections alive and survives container recreation.
- CI pins every action by commit and govulncheck by version; `latest` moves only
  for the newest release.

## Upgrade from v1.6.1

No storage-format migration is required; completion records of multipart
uploads live in `root_dir/.sebastian/multipart-completed/`. Before starting
v1.7.0, check the configuration — it now refuses to start when:

- an enabled gateway has no credentials and no `allow_anonymous: true`, or only
  one of its two credentials. The image enables S3 and the web UI by default, so
  a container started without credentials now stops with an explicit message;
- a credential still starts with `changeme`;
- an environment value does not parse (`SEBASTIAN_S3_ENABLED=ture`, a size with
  a unit, a duration without one).

With the shipped compose file, `.env` must set `S3_ACCESS_KEY`, `S3_SECRET_KEY`,
`HTTP_USERNAME` and `HTTP_PASSWORD`.

CompleteMultipartUpload, PutObject and CopyObject now return the object's
size-and-time ETag instead of the multipart composite MD5; clients that compared
the Complete ETag with a locally computed composite value must use `HEAD`. A
web UI upload over the limit answers `413` instead of `400`.

If objects were uploaded with aws-chunked bodies through v1.6.0 or earlier, run
`docker exec sebastian find-aws-chunked` and compare the files it lists with
their originals.

## Validation

Local checks passed with Go 1.26.10: full macOS race suite, vet, Windows
cross-build, source and binary vulnerability scans. Each fix is covered by a
regression test that fails without it; live daemon probes confirmed copies,
folder markers, conditional requests, streamed UI uploads and the refused root
deletion.
