# Sebastian v1.8.0

A hardening and performance release on top of [v1.7.0](v1.7.0.md).

## Changes

### Security and hardening

- **Path and symlink safety across all gateways:** symlink targets (including
  dangling symlinks and symlink loops) are resolved consistently against
  `root_dir` and never escape the root. Special files (FIFOs, devices) are
  opened non-blocking or rejected so a named pipe cannot stall a gateway worker.
- **Strict configuration validation:** unknown YAML fields, duplicate listener
  ports across enabled gateways, whitespace-only credentials, and invalid
  multipart bounds (`min_part_bytes > max_part_bytes` against defaults) are
  refused at startup.
- **Gateway parity and limits:**
  - SFTP: `SETSTAT`/`FSETSTAT` enforce `max_upload_bytes` on truncate, rename
    of root is rejected, concurrent SFTP sessions per SSH connection are
    bounded (16), and active SFTP sessions drain cleanly on `SIGTERM`.
  - WebDAV: `DELETE`, `MOVE`, and `COPY` enforce descendant locks, directory
    copies skip scratch/reserved files, and `GET` sets
    `X-Content-Type-Options: nosniff`.
  - HTTP UI: JSON action bodies are capped at 64 KiB and uploads/deletes share
    the same root/visibility safeguards as S3 and WebDAV.
  - S3: virtual-host matching is case-insensitive and supports IPv6 `Host`
    headers.

### Performance

- **Lock offloading across `fileops`, multipart, and gateways:** WebDAV `COPY`
  stages outside the volume lock, `OpenWriter` seeds and flushes staged files
  before taking the commit lock, multipart `Abort` moves aborted directories to
  trash outside the hot lock, and `RecoverIfNeededLocked` skips redundant
  journal scans once clean.

### Build and CI

- `Dockerfile` pins UID/GID `1000:1000`, uses `TARGETOS`/`TARGETARCH` for
  native cross-builds, and injects the release version via `-ldflags` from the
  `VERSION` build arg.
- CI adds a live daemon smoke test and checks Windows cross-builds.

## Upgrade from v1.7.0

No storage-format migration is required. Before restarting, verify your YAML
config has no unknown keys, duplicate listener ports, or whitespace-only
credentials. Coming from v1.6.x, read the
[v1.7.0 upgrade notes](v1.7.0.md#upgrade-from-v161) first.

## Validation

Verified with Go `-race`, `go vet`, Windows cross-build, and a 5-suite
cross-protocol Docker stand (corner cases, 4-protocol contention with
concurrent 20 MiB WebDAV `COPY`, 64-part S3 multipart stress, real Linux 8 MiB
tmpfs `ENOSPC`, and graceful `SIGTERM`).

## Images

Images are published for `linux/amd64` and `linux/arm64`:

```sh
docker pull solkin/sebastian:1.8.0
```

Version aliases: `1.8`, `1` and `latest`.
