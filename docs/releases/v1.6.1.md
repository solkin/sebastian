# Sebastian v1.6.1

S3 uploads now decode and verify supported streaming bodies, and filesystem
listing remains complete beyond 100000 objects. Release builds use Go 1.26.10
with updated SSH dependencies.

## Changes

- PutObject and UploadPart decode signed `aws-chunked` payloads, signed payloads
  with trailers, and unsigned payloads with checksum trailers before storing
  bytes. Chunk/trailer signatures, declared decoded length and flexible checksums
  are verified before publication.
- Rejected bodies preserve the previous object or part. Upload limits count
  decoded bytes. Unsupported streaming variants and streaming bodies on other
  operations return an explicit error before mutation.
- ListObjects V1/V2 retain at most `max-keys` plus one candidate and read
  directories in batches. Pagination no longer silently stops after the first
  100000 entries. Deep pages still scan the matching filesystem namespace.
- The module and Docker build use Go 1.26.10; `golang.org/x/crypto` is v0.56.0
  and `golang.org/x/sys` is v0.47.0.
- CI checks source and release-binary vulnerabilities before image publication,
  alongside race tests, vet and the Windows build. Crash-injection tests keep
  their child at its checkpoint until SIGKILL actually terminates it.

## Upgrade from v1.6.0

No configuration or storage-format migration is required. Upgrade every endpoint
accepting S3 uploads. Earlier versions could acknowledge an `aws-chunked` upload
while storing its framing instead of the decoded bytes. Compare affected existing
objects with their original checksums and upload the originals again when they
differ; upgrading cannot repair those objects automatically. Check completed
multipart objects as well as single-part uploads.

## Validation

Local checks passed with Go 1.26.10: full macOS and Linux race suites, vet,
Windows cross-build, source and Docker-binary vulnerability scans. Scans reported
no reachable vulnerabilities. Regression coverage includes published AWS
signature/checksum vectors, rejected upload preservation and a real filesystem
listing with 100001 files; live daemon probes confirmed decoded storage and
checksum rejection.

## Images

Images are published for `linux/amd64` and `linux/arm64`:

```sh
docker pull solkin/sebastian:1.6.1
```

Version aliases: `1.6`, `1` and `latest`.
